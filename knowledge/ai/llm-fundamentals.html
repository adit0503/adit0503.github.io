LLM Fundamentals — Transformers, Tokens & Sampling

The mental model an engineer needs before building on LLMs — how transformers and attention work, what tokens really are, why context windows are limited, how decoding and sampling produce text, and where the cost and latency actually come from.

It's Next-Token Prediction

At its core, an LLM does one thing: given a sequence of tokens, predict a probability distribution over the next token. Text generation is that step run in a loop — append the chosen token, predict again, repeat. Everything else (reasoning, code, chat) is emergent behavior on top of this single objective.

🔑 The one thing to internalize:

An LLM is a probabilistic next-token predictor, not a database or a reasoner. Hallucination isn't a bug bolted on — it's the same mechanism that produces correct text, applied where the model has no grounding. That's why RAG and grounding matter.

The Transformer & Attention

The transformer architecture replaced recurrence with self-attention, which lets every token look at every other token in the sequence and weigh their relevance. This is what captures long-range context ("it" refers to which noun?) and enables massive parallelism during training.

  • Self-attention — each token computes Query, Key, and Value vectors; attention scores = how much each token attends to others.
  • Multi-head attention — several attention computations in parallel, each learning different relationships.
  • Feed-forward layers — per-token transformations stacked between attention layers.
  • Decoder-only — modern LLMs (GPT, Claude, Llama) use causal (left-to-right) attention: a token can only attend to earlier tokens.
⚠️ Attention is quadratic:

Self-attention cost grows with the square of sequence length. Doubling the input roughly quadruples attention compute — the core reason long contexts are expensive and slow, and why techniques like caching and efficient attention exist.

Tokens & Tokenization

Models don't see words or characters — they see tokens, sub-word units produced by a tokenizer (BPE and variants). "tokenization" might be 2–3 tokens; a rare word or a code symbol may be several.

  • Rough rule of thumb for English: ~4 characters or ~0.75 words per token.
  • You pay per token (input + output), and context limits are counted in tokens.
  • Non-English text and code often tokenize less efficiently — more tokens per character.
  • Tokenization explains quirks like poor arithmetic and character-counting: the model never sees individual digits/letters cleanly.

Context Windows & KV Cache

The context window is the maximum number of tokens (prompt + generated output) the model can attend to at once. Everything the model "knows" for a request must fit here — system prompt, history, retrieved chunks, and the answer.

  • KV cache — during generation, the Key/Value vectors of prior tokens are cached so each new token doesn't recompute the whole sequence. This is the main memory consumer at inference.
  • Lost in the middle — models attend most strongly to the start and end of long contexts; information buried in the middle is easily missed. Put critical context at the edges.
  • Bigger isn't free — a large window enables long-context prompting but costs more and can dilute focus. Retrieve precisely rather than stuffing.

Decoding & Sampling

The model outputs a probability distribution; the decoding strategy turns it into a chosen token.

  • Temperature — flattens (high) or sharpens (low) the distribution. 0 is near-deterministic (best for factual/grounded tasks); higher adds creativity and variability.
  • Top-p (nucleus) — sample only from the smallest set of tokens whose cumulative probability ≥ p.
  • Top-k — sample only from the k most likely tokens.
  • Greedy — always take the most likely token; deterministic but can be repetitive.
💡 Practical default:

For RAG, extraction, and anything where correctness matters, use temperature 0. Raise temperature only for brainstorming or varied copy. If you need reproducibility, pin temperature and the model version.

Pretraining, SFT & RLHF

  1. Pretraining — next-token prediction over a huge corpus; learns language, facts, and reasoning patterns. Expensive, done once.
  2. Supervised fine-tuning (SFT) — train on curated instruction/response pairs so the model follows instructions.
  3. Preference alignment (RLHF / DPO) — tune toward human-preferred, helpful, harmless responses.

Understanding this explains why base models complete text while instruct models follow directions, and why "knowledge" is frozen at the pretraining cutoff — the motivation for retrieval.

Limitations You Design Around

  • Knowledge cutoff — no awareness of events after training → use RAG/tools.
  • Hallucination — confident fabrication when ungrounded → ground and cite.
  • Context limits — finite window → retrieve, summarize, chunk.
  • Non-determinism — same prompt can vary → temperature 0, version pinning, evals.
  • No true state — each call is stateless; memory is something you engineer.

Interview Questions

In one sentence, what does an LLM actually do?

It predicts a probability distribution over the next token given the preceding tokens, and generates text by sampling that distribution repeatedly in a loop. All higher-level behavior — chat, reasoning, code — emerges from this single objective, which is also why it hallucinates: fabrication uses the exact same mechanism as correct generation, just without grounding.

Why are long contexts expensive?

Self-attention scales quadratically with sequence length — every token attends to every other token, so doubling the input roughly quadruples attention compute. Memory also grows because the KV cache stores Key/Value vectors for all prior tokens. That's why you retrieve precise, small context via RAG instead of stuffing whole documents, and why prompt caching exists to amortize a stable prefix.

What is a token and why does it matter operationally?

A token is a sub-word unit from the tokenizer (roughly 4 characters of English). It matters because you're billed per input and output token, context limits are measured in tokens, and non-English text and code tokenize less efficiently, inflating both cost and context usage. Tokenization also explains weak arithmetic and character counting — the model never cleanly sees individual digits or letters.

How does temperature affect output, and what should you use for RAG?

Temperature scales the sharpness of the next-token distribution: low values concentrate probability on the top tokens (more deterministic), high values flatten it (more diverse and creative). For RAG, extraction, and factual tasks, use temperature 0 for consistency and to reduce drift. Reserve higher temperatures for creative generation. For reproducibility, pin temperature and the model version together.

What's the "lost in the middle" problem?

LLMs attend most strongly to the beginning and end of a long context and can overlook information placed in the middle, so recall degrades for buried content even when it's within the window. Mitigate by retrieving fewer, more relevant chunks, reranking so the best evidence lands at the edges, and not relying on giant stuffed prompts to surface the one fact that matters.
