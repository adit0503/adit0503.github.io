Why LLMOps Differs from MLOps

Classic ML has a fixed label and a clear accuracy metric. GenAI outputs are open-ended and non-deterministic, "correctness" is often subjective, and behavior depends on prompts and retrieved context, not just weights. LLMOps therefore leans on curated eval sets, LLM judges, guardrails, and heavy tracing rather than a single accuracy number.

🔑 First principle:

You cannot ship or improve a GenAI system without an evaluation set. Build a golden dataset of inputs and expected outputs/sources before you optimize anything.

Evaluation

  • Offline eval — run a fixed dataset through each version; compare metrics before promotion.
  • Online eval — monitor live traffic: user feedback (👍/👎), acceptance rate, escalation rate.
  • Reference-based — compare to a gold answer (exact match, semantic similarity).
  • Reference-free — score properties like faithfulness and relevance without a gold answer (needed at scale).
  • RAG-specific — retrieval (recall@k, nDCG) and generation (faithfulness, answer relevance) measured separately.

LLM-as-Judge

A strong model scores outputs against a rubric — useful when human labeling can't scale. Make it reliable:

  • Give a precise rubric and a scoring scale; ask for a brief justification.
  • Prefer pairwise comparison (A vs B) over absolute scores — it's more consistent.
  • Calibrate the judge against human labels on a sample; watch for position and verbosity bias.
  • Use a different/stronger model as judge than the one under test where possible.
⚠️ Judges are estimators, not oracles:

LLM judges have biases and can be gamed. Validate them against human ratings periodically and treat their scores as directional, especially for high-stakes decisions.

Guardrails & Safety

  • Input — prompt-injection and jailbreak detection, PII scrubbing, topic restriction.
  • Output — toxicity/safety filters, PII redaction, format/schema validation, grounding checks.
  • Managed options — Bedrock Guardrails, Databricks/MLflow safety judges.
  • Fail modes — decide default-deny vs safe fallback per action; log every block.

Observability & Tracing

Trace every request end to end: prompt, retrieved chunks, tool calls, model version, tokens, latency, cost, and the final output. This is how you debug quality issues (usually retrieval) and detect drift.

  • Tools: LangSmith, LangFuse, MLflow Tracing, Bedrock model-invocation logging.
  • Capture user feedback inline and link it to the trace for later eval.
  • Alert on spikes in latency, cost, refusal/guardrail rate, and negative feedback.

Prompt & Version Management

  • Version prompts like code — in source control, with change review.
  • Pin model versions — provider updates can shift behavior; upgrade deliberately and re-evaluate.
  • Track the full config — prompt + model + retrieval params + tools as one versioned unit.
  • A/B and canary — roll out changes to a slice, compare eval metrics, then expand.

Latency & Cost

  • Model tiering — route easy requests to a small model, hard ones to a large one.
  • Prompt caching — reuse stable prefixes (system prompt, reference docs) at a discount.
  • Semantic caching — return a cached answer for near-duplicate queries.
  • Trim context — retrieve fewer, better chunks; rerank instead of stuffing.
  • Streaming — stream tokens to cut perceived latency.
  • Batch & async — batch offline embedding/generation; use provisioned throughput for steady load.
💡 Measure per-request cost:

Track tokens and dollars per request in your traces. Cost regressions hide in longer prompts and larger top-k just as often as in model choice.

Interview Questions

How is LLMOps different from traditional MLOps?

Traditional MLOps optimizes a model with fixed labels and a clear accuracy metric. GenAI outputs are open-ended and non-deterministic, correctness is often subjective, and behavior depends on prompts and retrieved context as much as weights. So LLMOps emphasizes curated evaluation sets, reference-free metrics and LLM-as-judge, guardrails, prompt/version management, and detailed tracing — rather than a single accuracy score and a retraining loop.

How do you make LLM-as-judge reliable?

Give a precise rubric and scale, require a short justification, and prefer pairwise comparison over absolute scoring for consistency. Calibrate the judge against human labels on a sample and monitor for position, verbosity, and self-preference bias. Use a stronger or different model as the judge than the one being evaluated, and treat scores as directional estimators — validate periodically, especially before high-stakes decisions.

A production RAG app slowly degraded. How do you find out why?

Lean on tracing. Compare recent traces to a healthy baseline: check whether retrieved chunks stopped containing the answer (stale index, source drift, embedding-version mismatch), whether the model version changed, or whether prompts/top-k changed. Run the golden eval set against the current config to localize the regression to retrieval vs generation. Correlate with negative user feedback and guardrail/refusal rates to pinpoint the affected query segment.

What levers reduce GenAI serving cost without hurting quality?

Model tiering (small model for easy tasks, large only for hard ones), prompt caching for stable prefixes, and semantic caching for repeat queries. Retrieve fewer, higher-quality chunks via reranking instead of stuffing context, cap max tokens, and use temperature 0 to avoid wasteful retries. Batch offline workloads and use provisioned throughput for steady load. Track per-request tokens/cost in traces to catch regressions from creeping prompt size.

Why pin model versions, and how do you upgrade safely?

Provider model updates can shift behavior and silently change outputs, breaking prompts tuned to the old version. Pin an explicit version so production is reproducible. To upgrade, run the new version against your golden eval set, compare metrics to the current baseline, then canary to a small traffic slice while monitoring feedback and guardrail rates before full rollout. Version the prompt, model, and retrieval config together as one unit.
