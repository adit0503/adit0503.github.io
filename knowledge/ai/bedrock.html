What Bedrock Is

Amazon Bedrock is a fully managed service that exposes foundation models from multiple providers (Anthropic Claude, Amazon Titan/Nova, Meta Llama, Mistral, Cohere) behind a single API, with no infrastructure to manage. It adds managed building blocks — Knowledge Bases (RAG), Agents, Guardrails, evaluation, and fine-tuning — so you assemble GenAI apps from AWS-native, IAM-governed components.

🔑 Why teams pick Bedrock:

Data stays in your AWS account, access is governed by IAM, models are swappable behind one API, and it integrates natively with S3, OpenSearch, Lambda, and CloudWatch — no data leaves your VPC boundary.

Models & the Converse API

The Converse API gives a single, model-agnostic interface for multi-turn chat, tool use, and multimodal input, so you can swap Claude for Llama without rewriting call code. InvokeModel remains for provider-specific payloads.

  • On-demand — pay per token, no commitment.
  • Provisioned throughput — reserved capacity for high, steady load.
  • Cross-region inference — route to available capacity for resilience.
Bedrock Converse API (boto3)
import boto3
client = boto3.client("bedrock-runtime")

resp = client.converse(
    modelId="anthropic.claude-3-5-sonnet-20241022-v2:0",
    messages=[{"role": "user",
               "content": [{"text": "Summarize this pipeline failure log."}]}],
    inferenceConfig={"temperature": 0, "maxTokens": 1024},
)
print(resp["output"]["message"]["content"][0]["text"])

Knowledge Bases (Managed RAG)

Bedrock Knowledge Bases give you RAG without building the pipeline yourself:

  • Data source — point it at S3 (also supported: web crawler, Confluence, SharePoint, Salesforce).
  • Chunking + embedding — managed, using Titan or Cohere embeddings; supports fixed, hierarchical, and semantic chunking.
  • Vector store — OpenSearch Serverless (default), Aurora pgvector, Pinecone, Redis, and others.
  • Retrieval APIs — Retrieve (get chunks) and RetrieveAndGenerate (get chunks + generate a cited answer in one call).
  • Advanced — metadata filtering, reranking, and structured/GraphRAG options.
💡 Build vs managed:

Start with a Knowledge Base for speed. Go custom when you need control over parsing (complex tables), bespoke chunking, or metadata the managed flow doesn't expose. You can mix: managed retrieval, custom generation.

Bedrock Agents

Bedrock Agents orchestrate multi-step tasks by combining an FM with tools and knowledge:

  • Action groups — tools defined by an OpenAPI schema, backed by Lambda functions or return-of-control to your code.
  • Knowledge base association — the agent retrieves context automatically as part of reasoning.
  • Orchestration — the agent plans, calls actions, observes results, and iterates (a managed ReAct loop).
  • Traces — full step-by-step reasoning traces for debugging and audit.
  • Multi-agent collaboration — a supervisor agent can delegate to specialized sub-agents.

Guardrails

Bedrock Guardrails apply configurable safety policies independent of the model, and can be attached to any model, Knowledge Base, or Agent:

  • Content filters — block hate, violence, sexual, and prompt-attack categories at tunable strengths.
  • Denied topics — define subjects the app must refuse.
  • Sensitive information — detect and redact/block PII.
  • Word filters — profanity and custom blocklists.
  • Contextual grounding checks — score responses for grounding in the retrieved source and relevance to the query, filtering hallucinations.

Security & Integration

  • IAM — fine-grained permissions on models, KBs, and agents.
  • VPC / PrivateLink — keep traffic off the public internet.
  • Encryption — KMS for data at rest; your data isn't used to train base models.
  • Governance — Lake Formation / IAM on the S3 source; CloudWatch + CloudTrail for logging and audit.
  • Cost controls — token metering, provisioned throughput, and model tiering (route simple calls to smaller/cheaper models).

Interview Questions

What does a Bedrock Knowledge Base give you over building RAG yourself?

It manages the whole retrieval pipeline: ingestion from S3/SharePoint/etc., chunking, embedding (Titan/Cohere), indexing into a vector store like OpenSearch Serverless, and retrieval via Retrieve / RetrieveAndGenerate with citations. You skip building and operating the pipeline and get IAM governance for free. You'd build custom only when you need control over parsing complex documents, bespoke chunking, or specialized metadata the managed flow doesn't expose.

How do Bedrock Agents execute actions?

Through action groups defined by an OpenAPI schema and backed by Lambda functions (or return-of-control to your own code). The agent runs a managed reasoning loop: it plans, selects an action, the Lambda executes it, and the result feeds back for the next step until the task completes. It can also pull context from an associated Knowledge Base and emit full traces for debugging and audit.

What is the contextual grounding check in Guardrails?

It scores a model response on two axes: grounding (is the answer supported by the retrieved source material?) and relevance (does it address the user's query?). Responses below your configured thresholds are blocked or flagged, which directly reduces hallucinations in RAG applications. Because Guardrails are model-independent, you can apply the same policy across different FMs, Knowledge Bases, and Agents.

Why use the Converse API instead of InvokeModel?

Converse gives a single, model-agnostic schema for multi-turn conversations, tool use, and multimodal content, so you can switch between Claude, Llama, Titan, etc. without rewriting request/response handling. InvokeModel requires provider-specific payload formats. Use Converse for portability and standard chat/tool workflows; drop to InvokeModel only when you need a provider-specific feature it doesn't cover.

How does Bedrock keep enterprise data secure?

Data stays within your AWS account and isn't used to train the base models. Access is governed by IAM at the model/KB/agent level, traffic can stay private via VPC endpoints/PrivateLink, and data is encrypted with KMS. Source data in S3 is governed by Lake Formation/IAM, and CloudTrail plus CloudWatch provide audit logging. This account-boundary model is a primary reason regulated industries choose Bedrock.
