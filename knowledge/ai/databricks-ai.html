Why GenAI on the Lakehouse

If your data already lives in Delta tables under Unity Catalog, building GenAI where the data sits avoids copying it into separate systems and keeps one governance model across raw data, features, embeddings, models, and endpoints. Databricks Mosaic AI is the umbrella for these capabilities.

🔑 The lakehouse advantage:

One catalog governs the source table, the vector index, the model, and the serving endpoint — so lineage and access control flow end to end instead of being re-implemented in a bolt-on vector DB.

Mosaic AI Vector Search

A serverless vector database integrated with Unity Catalog. Its defining feature is Delta Sync: point an index at a Delta table and it stays automatically in sync as rows change — no separate embedding pipeline to operate.

  • Managed embeddings — Databricks computes embeddings from a text column using a served embedding model, or
  • Self-managed embeddings — you supply the vector column and it indexes them.
  • Delta Sync index — incremental updates as the source table changes (via Change Data Feed).
  • Direct Vector Access index — you write vectors yourself for full control.
  • Filtered & hybrid search — metadata filters plus keyword+vector similarity.
Delta Sync vector index (Python SDK)
from databricks.vector_search.client import VectorSearchClient
vsc = VectorSearchClient()

vsc.create_delta_sync_index(
    endpoint_name="vs_endpoint",
    index_name="main.rag.docs_index",
    source_table_name="main.rag.docs",       # Delta table
    pipeline_type="TRIGGERED",                 # or CONTINUOUS
    primary_key="id",
    embedding_source_column="content",         # managed embeddings
    embedding_model_endpoint_name="databricks-bge-large-en",
)

Model Serving & Gateway

  • Model Serving — serverless REST endpoints for custom models, fine-tuned LLMs, or embedding models, autoscaling to zero.
  • Foundation Model APIs — pay-per-token access to hosted open models, plus provisioned throughput for dedicated capacity.
  • External models / AI Gateway — a governed proxy to third-party providers (including Claude/Bedrock, OpenAI) with a unified interface, rate limits, usage tracking, and key management.
💡 One endpoint, many backends:

The AI Gateway lets you swap the underlying model provider without changing app code, and centralizes credentials, quotas, and usage logging — the same portability benefit Bedrock's Converse API provides on AWS.

Agent Framework & RAG

The Mosaic AI Agent Framework is used to build, log, and deploy RAG and agent applications:

  • Author chains/agents (LangChain, LlamaIndex, or custom) and log them as MLflow models.
  • Retrieve from Vector Search, call a served LLM, and return cited answers.
  • Deploy as a Model Serving endpoint with a built-in review app for human feedback.
  • Capture request/response traces for evaluation and monitoring.

Evaluation with MLflow

MLflow LLM evaluation (Agent Evaluation) scores RAG/agent outputs with built-in LLM judges — correctness, groundedness, relevance, and safety — against an evaluation dataset, and tracks results across versions so you can prove a change actually improved quality before shipping.

Unity Catalog Governance

  • Data + AI assets in one catalog — tables, volumes (unstructured files), functions/tools, models, and vector indexes are all governed objects.
  • Lineage — trace an answer back through the endpoint, index, and source table.
  • Access control — the same grants protect the source data and the retrieval index, so a user can't retrieve what they can't read.
  • Volumes — govern raw unstructured files (PDFs, images) that feed the ingestion pipeline.

Interview Questions

What makes Databricks Vector Search different from a standalone vector DB?

Delta Sync: you point an index at a Delta table and it keeps the vectors in sync automatically as the table changes (via Change Data Feed), so there's no separate embedding pipeline to build and operate. It's governed by Unity Catalog, so access control and lineage extend from the source table to the index. This tight lakehouse integration is the main reason to choose it when your data already lives in Delta.

Managed vs self-managed embeddings in Vector Search?

With managed embeddings you specify a text column and an embedding model endpoint, and Databricks computes and refreshes the vectors for you — simplest to operate. With self-managed (Direct Vector Access), you compute and write vectors yourself, giving full control over the embedding model, chunking, and update logic at the cost of running that pipeline. Choose managed for speed, self-managed when you need custom control.

What does the AI Gateway / external models feature provide?

A governed proxy to model providers (Databricks-hosted models and third parties like Claude/Bedrock or OpenAI) behind one unified endpoint. It centralizes credential management, rate limiting, and usage/cost tracking, and lets you swap the backing model without changing application code. It's the lakehouse equivalent of a model-agnostic gateway, giving portability and central governance over all LLM traffic.

How does Unity Catalog govern a RAG application end to end?

All the assets — source Delta tables, volumes holding raw files, the vector index, the served model, and functions/tools — are Unity Catalog objects with grants and lineage. The same access controls that protect the source data protect the retrieval index, so users can't retrieve content they can't read. Lineage lets you trace a generated answer back through the endpoint and index to the exact source rows, which is essential for audit in regulated domains.

How would you prove a RAG change improved quality on Databricks?

Use MLflow Agent Evaluation. Curate an evaluation dataset of questions with expected answers/sources, run built-in LLM judges for correctness, groundedness, relevance, and safety, and log the scores per model version. Compare the new version against the baseline on the same dataset before promoting it. Combine with production trace capture so offline eval and live monitoring use consistent metrics.
